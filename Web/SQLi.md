# SQLi
## 1. What is SQLi (SQL Injection)?
`SQL injection`은 공격자가 어플리케이션의 `데이터베이스 쿼리`에 `간섭`할 수 있게 하는 보안 결함 임. 공격자는 다른 사용자의 정보나 어플리케이션에서 사용할 수 있는 모든 데이터를 비롯해 접근 권한이 없는 데이터를 `조회`, `수정` 또는 `삭제` 가능. 이러한 행위는 어플리케이션의 기능이나 콘텐츠를 영구적으로 변경하거나, 서버를 침해하거나, 서비스 거부를 일으킬 수 있음.

예를들어 웹사이트가 아래와 같이 동작 한다고 할 때
- 사용자가 로그인, 검색, 상품 보기 같은 행동을 함
- 웹사이트가 그 정보를 데이터베이스에 물어봄
- 데이터베이스가 답을 주면 화면에 보여줌

이때 웹사이트가 사용자가 입력한 내용을 `제대로 확인하지 않고` 그대로 데이터베이스에 넘기면 문제가 생김.

비유:
식당에서 손님이 주문지에 
"김치찌개 하나"라고 적어야 하는데
"김치찌개 하나, 주방 금고 비밀번호, 매출 전표" 라고 적음
그런데 주방장이 주문지를 `확인도 안 하고` 그대로 실행해 버리는 상황.

로그인 예시:
```
SELECT * FROM users WHERE username = 'usernameInput' AND password = 'passwordInput';
```
이때 어플리케이션이 입력값을 `제대로 검증하지 않고` 쿼리에 그대로 붙여 넣으면, 공격자가 SQL 문법 자체를 조작 가능.

공격자가 비밀번호 칸에 다음과 같이 입력한다고 가정.
```
' OR '1'='1
```
실제 실행되는 쿼리
```
SELECT * FROM users WHERE username = 'usernameInput' AND password = '' OR '1'='1';
```
`'1'='1'` 은 항상 참이기 때문에, 비밀번호가 틀려도 로그인 우회 가능.

**쉽게 비유하면**
- 정상적인 웹사이트 = 식당에서 손님이 주문한 메뉴만 정확히 만들어 주는 것
- SQLi가 있는 웹사이트 = 손님이 주문지에 "음식 말고도 주방에 있는 전체 메뉴와 금고에 있는 돈도 가져와"라고 적었는데, 주방장이 그대로 실행하는 것

**핵심**
- SQLI는 웹사이트가 사용자 입력을 SQL 쿼리에 그대로 넣어서 발생
- 브라우저가 아닌 `데이터베이스`를 직접 조작
- 데이터 탈취, 변조, 삭제, 경우에 따라 서버 명령 실행까지 가능

## 2.SQLi를 통해 가능한 공격들
공격자는 데이터베이스에 보내는 쿼리를 조작할 수 있음.

**실제로 할 수 있는 일들**
- 데이터 열람 : 다른 사용자의 개인정보, 비밀번호 해시, 신용카드 정보 등 조회
- 인증 우회 : 로그인 없이 관리자 계정으로 접속
- 데이터 변조/삭제 : 다른 사람의 정보 수정, 레코드 삭제
- 권한 상승 : 일반 사용자 계정을 관리자 권한으로 변경
- 데이터베이스 서버 장악 : 일부 DBMS에서 OS 명령 실행 (`xp_cmdshell`, `LOAD_FILE` 등)
- 다른 시스템으로 확장 : 내부 네트워크 정보 수집 후 추가 공격

## 3. SQLi 유형
### 3.1 Error-based SQLi
웹사이트가 데이터베이스와 통신하다 `에러가 발생했을 때`, 그 에러 메시지를 사용자에게 그대로 보여주면서 생기는 취약점.\
정상적인 경우에는 에러 메세지는 개발자만 봐야 하지만,\
일부 사이트는 "에러가 났습니다" 같은 메시지 안에 `데이터베이스가 반환한 원본 에러`를 그대로 출력 함.\
공격자는 이 점을 이용하여 `의도적으로 에러를 발생`시키고,\
에러 메시지 안에 들어 있는 정보를 읽어냄.\

**왜 가능한가?**
- 데이터베이스가 반환하는 `에러 메세지`를 통해 정보를 추출
- 에러에 테이블명, 컬럼명, 데이터 일부가 포함되는 경우

**예시**
로그인 예시:
```
SELECT * FROM users WHERE username = 'usernameInput' AND password = 'passwordInput';
```

공격자가 username 칸에 다음과 같이 입력한다고 가정.
```
' AND 1=CONVERT(1,@@version) -- -
```

실제 실행되는 쿼리
```
SELECT * FROM users WHERE username = '' AND 1=CONVERT(int, @@VERSION) -- - AND password = 'passwordInput';
```
**쿼리 설명**
| 부분     | 의미                | 설명    |
| ------ | ------------------------- | ---------------- |
| `'`  | 문자열 닫기                   | 원래 쿼리의 따옴표를 닫아서 SQL 문법 탈출          |
| `AND 1=`  | 조건 추가            | 뒤에 오는 값과 비교하도록 만듦 |
| `CONVERT(int, ...)` | 강제 형변환   | 문자열을 숫자로 바꾸려고 시도 -> **에러 발생**  |
| `@@version`  | 버전 조회         | 데이터베이스 버전 정보를 가져옴       |
| `-- -` | 주석 처리 | 뒤에 남은 원래 쿼리를 무시        |

**실행흐름**
1. 공격자가 입력값에 위 페이로드를 넣음
2. 데이터베이스가 `@@version` 값을 가져옴
3. 이 version 정보를 `CONVERT(int, ...)`로 **숫자로 바꾸려고** 시도
4. 문자열은 숫자가 될 수 없으므로 **에러 발생**
5. 에러 메세지에 버전 정보가 포함되어 화면에 출력됨
6. 공격자는 메세지에서 정보를 그대로 읽어냄

**얻을 수 있는 정보**
- 데이터베이스 종류와 버전
- 데이터 베이스 이름
- 테이블 목록
- 컬럼 목록
- 실제 데이터

**장점과 한계**

장점
- 직관적이고 빠름
- 한 번의 요청으로 정보를 바로 확인 가능
- 결과가 화면에 출력되지 않아도 사용 가능

한계
- 웹사이트가 `에러 메세지를 숨기면` 사용불가
- 최신 웹 어플리케이션은 대부분 에러를 사용자에게 보여주지 않음
- DBMS마다 에러를 유발하는 문법이 조금씩 다름

### 3.2 Union-based SQLi
웹사이트가 데이터베이스에서 가져온 결과를 **화면에 그대로 출력**할 때 생기는 취약점.\
정상적인 경우에는 사용자가 요청한 데이터만 보여줘야 하지만,\
일부 사이트는 입력값을 제대로 검증하지 않아서 `UNION`이라는 문법으로 **다른 테이블의 데이터를 원래 결과에 강제로 붙일 수** 있다.\
공격자는 이 점을 이용해서
원래 보여주려던 결과 뒤에 자신이 원하는 데이터(다른 사용자의 정보, 비밀번호 등)를 붙여서\
**화면에 같이 출력**되게 만듬.
즉,\
**결과를 보여주는 화면을 이용해서, 원래는 볼 수 없는 데이터를 끌어와 보여주는 기법**.

정상 쿼리:
```
SELECT title, content FROM products WHERE id = 'idInput';
```

공격자 쿼리:
```
1' UNION SELECT username, password FROM users --
```

실제 실행되는 쿼리:
```
SELECT title, content FROM products WHERE id = '1' UNION SELECT username, password FROM users --
```

원래 상품 정보 결과에 **user 테이블의 username과 password** 가 뒤에 붙어서 같이 출력됨.\
즉, **화면에 결과가 출력되는 곳**을 이용해서 다른 테이블의 데이터를 끌어오는 기법임.

**조건**
`UNION`을 사용하려면 다음 두 가지 조건이 맞아야 함.
1. **컬럼 개수가 동일**해야 함
2. **각 컬럼의 데이터 타입이 호환**되어야 함
예를 들어 원래 쿼리가 3개 컬럼을 반환하는데,
`UNION SELECT` 쪽에서 2개만 반환하면 에러가 남.

**실행흐름**
1. 컬럼 개수 찾기\
  가장 많이 쓰이는 방법은 `ORDER BY` 임
```
' ORDER BY 1 -- -
' ORDER BY 2 -- -
' ORDER BY 3 -- -
' ORDER BY 4 -- -
```
`ORDER BY 3` 까지는 정상적으로 동작하고 `ORDER BY 4`에서 에러가 나면 -> **컬럼은 3개**라는 뜻임

다른 방법으로는 `UNION SELECT NULL` 을 하나씩 늘려가며 확인
```
' UNION SELECT NULL -- -
' UNION SELECT NULL, NULL -- -
' UNION SELECT NULL, NULL, NULL -- -
```
에러가 나지 않는 시점이 컬럼 개수임.

2. 어느 컬럼이 화면에 출력되는지 확인\
  컬럼 개수를 알았으면, 어떤 위치에 데이터를 넣어야 화면에 보이는지 테스트 함.
```
' UNION SELECT 'a', 'b', 'c' -- -
```
화면에 `a`, `b`, `c` 중 어떤 것이 보이는지 확인함.\
보이는 위치가 바로 **데이터를 출력할 수 있는 컬럼**임.

3. 실제 데이터 추출\
   출력 가능한 컬럼 위치에 원하는 데이터를 넣음.
```
' UNION SELECT username, password, NULL FROM users -- -
```
이렇게 하면 원래 결과 대신(또는 함께) `users` 테이블의 데이터가 나타남.

**실제 쿼리 예시**

원래 쿼리 : 
```
SELECT name, description FROM products WHERE id = '1';
```
공격 후 :
```
SELECT name, description FROM products WHERE id = '1' UNION SELECT username, password FROM USERS -- -;
```
화면에는 상품 정보와 함께(또는 대신) 사용자 계정 정보가 출력됨.

**자주 보이는 쿼리**

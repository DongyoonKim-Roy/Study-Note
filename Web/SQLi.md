# SQLi
## 1. What is SQLi (SQL Injection)?
`SQL injection`은 공격자가 어플리케이션의 `데이터베이스 쿼리`에 `간섭`할 수 있게 하는 보안 결함 임. 공격자는 다른 사용자의 정보나 어플리케이션에서 사용할 수 있는 모든 데이터를 비롯해 접근 권한이 없는 데이터를 `조회`, `수정` 또는 `삭제` 가능. 이러한 행위는 어플리케이션의 기능이나 콘텐츠를 영구적으로 변경하거나, 서버를 침해하거나, 서비스 거부를 일으킬 수 있음.

예를들어 웹사이트가 아래와 같이 동작 한다고 할 때
- 사용자가 로그인, 검색, 상품 보기 같은 행동을 함
- 웹사이트가 그 정보를 데이터베이스에 물어봄
- 데이터베이스가 답을 주면 화면에 보여줌

이때 웹사이트가 사용자가 입력한 내용을 `제대로 확인하지 않고` 그대로 데이터베이스에 넘기면 문제가 생김.

비유:
식당에서 손님이 주문지에 
"김치찌개 하나"라고 적어야 하는데
"김치찌개 하나, 주방 금고 비밀번호, 매출 전표" 라고 적음
그런데 주방장이 주문지를 `확인도 안 하고` 그대로 실행해 버리는 상황.

로그인 예시:
```
SELECT * FROM users WHERE username = 'usernameInput' AND password = 'passwordInput';
```
이때 어플리케이션이 입력값을 `제대로 검증하지 않고` 쿼리에 그대로 붙여 넣으면, 공격자가 SQL 문법 자체를 조작 가능.

나쁜 사람이 비밀번호 칸에 다음과 같이 입력한다고 가정.
```
' OR '1'='1
```
실제 실행되는 쿼리는
```
SELECT * FROM users WHERE username = 'usernameInput' AND password = '' OR '1'='1';
```
`'1'='1'` 은 항상 참이기 때문에, 비밀번호가 틀려도 로그인 우회 가능.

**쉽게 비유하면**
- 정상적인 웹사이트 = 식당에서 손님이 주문한 메뉴만 정확히 만들어 주는 것
- SQLi가 있는 웹사이트 = 손님이 주문지에 "음식 말고도 주방에 있는 전체 메뉴와 금고에 있는 돈도 가져와"라고 적었는데, 주방장이 그대로 실행하는 것

**핵심**
- SQLI는 웹사이트가 사용자 입력을 SQL 쿼리에 그대로 넣어서 발생
- 브라우저가 아닌 `데이터베이스`를 직접 조작
- 데이터 탈취, 변조, 삭제, 경우에 따라 서버 명령 실행까지 가능

## 2.SQLi를 통해 가능한 공격들
공격자는 데이터베이스에 보내는 쿼리를 조작할 수 있음.

**실제로 할 수 있는 일들**
- 데이터 열람 : 다른 사용자의 개인정보, 비밀번호 해시, 신용카드 정보 등 조회
- 인증 우회 : 로그인 없이 관리자 계정으로 접속
- 데이터 변조/삭제 : 다른 사람의 정보 수정, 레코드 삭제
- 권한 상승 : 일반 사용자 계정을 관리자 권한으로 변경
- 데이터베이스 서버 장악 : 일부 DBMS에서 OS 명령 실행 (`xp_cmdshell`, `LOAD_FILE` 등)
- 다른 시스템으로 확장 : 내부 네트워크 정보 수집 후 추가 공격
